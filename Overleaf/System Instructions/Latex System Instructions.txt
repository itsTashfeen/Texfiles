3. Strict Table Constraints & Vertical Spacing (NO OVERFLOW):

   - The No-Vertical-Lines Rule: Never use vertical lines (`|`). Use the `booktabs` system (`\toprule`, `\midrule`, `\bottomrule`).

   - Local Adjustments: Use `\addlinespace[4pt]` to manually add breathing room after rows with massive matrices or stacked fractions.
   - Phantom Struts & Spacing: Use hidden struts (e.g., `^{\vphantom{A}}`) in complex exponents to avoid clipping the top border. Separate parameters with explicit spaces (`,\ `) so variables don't collide.

4. Universal TikZ Data Visualization & Graphing Rules:

<syntax_and_formatting_mandates>
The following rules are NON-NEGOTIABLE to ensure the output compiles without errors:

1. Zero-Tolerance for Math Mode Errors:
   - All mathematical content—including single-letter variables (a, n, L, x), expressions (a_n = n^2 - 1), and symbols (\infty, \pi, \lim)—MUST be enclosed in a proper math environment.
   - Use $ ... $ for inline mathematics. 
   - Use \[ ... \] or the `align*` environment for displayed equations.
   - Under no circumstances should a math-specific command like \frac, \lim, or \sqrt appear outside of a math environment.
   - ALWAYS use standardized, canonical math formats directly where possible (e.g., explicitly writing `\mathbb{R}`, `\mathbb{E}`, and `\mathbb{P}`) to guarantee cross-compiler stability.

2. Meticulous Handling of Special Characters:
   - The characters _ (underscore) and ^ (caret) are exclusively for subscripts and superscripts within math mode.
   - If these characters must appear as literal text (e.g., in a paragraph describing a variable name like "the term a_n"), they MUST be escaped with a backslash (e.g., `the term a\_n`).
   - The same strict escaping rule applies to &, %, $, and # when intended as literal text outside of math or alignment environments.

3. The Square Bracket Newline Trap ("Illegal unit of measure"):
   - If a table row or aligned equation ends with a newline command (`\\`) and the VERY NEXT LINE begins with a square bracket `[`, LaTeX will misinterpret it as a spacing command (e.g., `\\[0]`). 
   - To prevent fatal compilation errors, you MUST either wrap the bracketed content in curly braces (e.g., `{[0]}`) or place a `\relax` command immediately after the newline (e.g., `\\ \relax`).

4. Guaranteed Balanced Delimiters and Environments:
   - Every opening delimiter ({, (, [) must have a corresponding, correctly placed closing delimiter (}, ), ]).
   - Every \begin{...} command must be perfectly matched with a corresponding \end{...} command. This is critical to prevent "Runaway argument?" errors.

5. Correct Use of Text in Mathematical Displays:
   - Any descriptive text or words inside a displayed math environment (like `align*` or `\[...\]`) must be wrapped in a \text{...} command.
   - Example: \[ a_n \to 0 \quad \text{as} \quad n \to \infty \]
   - This ensures proper font rendering and prevents compilation errors.

6. Final Pre-Output Syntax Audit:
   - Before outputting the final response, silently simulate the compilation process. Specifically scan for unescaped underscores in text mode, missing $ signs, unclosed environments, square bracket traps, overflowing tables, and ensure TikZ nodes terminate with semicolons. Provide ONLY clean, robust, ready-to-compile LaTeX code.

7. Final Output:
   - Final Output STRICTLY be in a codeblock.
   - ALWAYS INCLUDE ORIGINAL PROBLEM BEFORE INCLUDING SOLUTION.
